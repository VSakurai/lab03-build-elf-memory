## 1. Build Pipeline (Етапи створення програми)

| Файл        | Етап          | Що містить                                          | Чи може CPU виконати безпосередньо? |
| :---------- | :------------ | :-------------------------------------------------- | :---------------------------------- |
| `program.c` | Source code   | Текст C-коду                                        | Ні                                  |
| `program.i` | Preprocessing | Розгорнутий C-код (з підключеними заголовками)      | Ні                                  |
| `program.s` | Compilation   | Assembly-код (текст)                                | Ні                                  |
| `program.o` | Assembly      | Object file (machine code + relocations + symbols)  | Ні (потрібне лінкування)            |
| `program`   | Linking       | Executable (ELF), готовий до завантаження в пам'ять | Так                                 |

**Пояснення:** `gcc` виконує всі 4 етапи автоматично. Але ми можемо розбити їх за допомогою `-E`, `-S`, `-c` та лінкування.

## 2. Preprocessing (program.i)

- **Чому `program.i` більший?** Тому що `#include <stdio.h>` замінюється на весь вміст файлу `stdio.h` (а він містить тисячі рядків оголошень функцій).
- **Що сталося з `#include`?** Директива preprocessing була виконана: вміст файлу `stdio.h` був "вставлений" у код.
- **Чи це машинний код?** Ні, це все ще C-код (текст).
- **Чи може CPU його виконати?** Ні, процесор не розуміє C.

## 3. Compilation (program.s)

- **Яка мова?** Assembly (Intel syntax).
- **Чи це machine code?** Ні, це текстова вистава інструкцій.
- **Для якої ISA?** x86-64 (оскільки ми використовували `-masm=intel`).
- **Чи видно `main` та `add`?** Так, це глобальні функції, вони мають мітки `main:` та `add:`.

## 4. Assembly → Object File (program.o)

- **Чому `cat program.o` виглядає інакше?** Тому що `program.o` — це двійковий файл (ELF relocatable object), а не текст. Він містить машинний код, таблицю символів та інформацію для лінкера.

## 5. Symbols (nm program.o)

- **Чи містить `program.o` реалізацію `add()`?** Так (символ `T add`).
- **Чи містить він `main()`?** Так (символ `T main`).
- **Чи містить він `printf()`?** Ні, `printf` позначений як `U` (undefined). Він буде знайдений під час лінкування в бібліотеці `libc`.

## 6. Linking та Linker Error

- **Помилка `undefined reference to 'calculate'`** виникла тому, що компілятор знав, що функція `calculate` існує (оголошення в `main.c`), але лінкер не знайшов її реалізації (у `calculate.c`).
- **Виправлення:** скомпілювати `calculate.c` в `calculate.o` і передати обидва об'єктні файли лінкеру.

## 7. ELF (readelf -h program)

| ELF property | Значення                      |
| :----------- | :---------------------------- |
| Class        | ELF64                         |
| Data         | 2's complement, little endian |
| Type         | EXEC (Executable file)        |
| Machine      | Advanced Micro Devices X86-64 |
| Entry point  | 0x401040 (або інша адреса)    |

**Що означає ELF64?** Це 64-бітний формат. Machine показує архітектуру x86-64.

## 8. ELF Sections (readelf -S program)

| Section   | Що містить                                                        |
| :-------- | :---------------------------------------------------------------- |
| `.text`   | Машинний код (функції `main`, `add`)                              |
| `.rodata` | Константи (рядки формату, string literals)                        |
| `.data`   | Ініціалізовані глобальні та статичні змінні (`global_value = 10`) |
| `.bss`    | Неініціалізовані глобальні та статичні змінні (`global_empty`)    |

## 9. .data та .bss (sections.c)

| Змінна                 | Секція                                 |
| :--------------------- | :------------------------------------- |
| `initialized`          | `.data`                                |
| `uninitialized`        | `.bss`                                 |
| `static_initialized`   | `.data`                                |
| `static_uninitialized` | `.bss`                                 |
| `message`              | `.rodata` (оскільки це `const char[]`) |

## 10. Розмір .bss (size sections)

- **Початковий розмір:** `text: ~1500, data: ~500, bss: ~8`
- **Після зміни на `int large_array[100000]`:** `bss` збільшився до ~400 008 байт (400 КБ).
- **Чи збільшився executable file?** Ні, розмір файлу майже не змінився.

**Центральне питання:** Чому велика `.bss` не збільшує розмір файлу?
Тому що `.bss` містить **неініціалізовані** дані. Їх не потрібно зберігати у файлі — вони просто займають місце в пам'яті під час виконання, і операційна система ініціалізує їх нулями. У файлі зберігається лише інформація про розмір `.bss` (у заголовку ELF), а не самі дані.

## 11. Dynamic Libraries (ldd program)

- **Чи є `printf()` всередині нашого executable?** Ні.
- **Що означає `.so`?** Shared Object (динамічна бібліотека).
- **Чому кілька програм можуть використовувати одну бібліотеку?** Тому що вона завантажується в пам'ять один раз, і всі програми можуть звертатися до неї.
- **Перевага:** Економія пам'яті та дискового простору, а також можливість оновлювати бібліотеку без перекомпіляції програм.

## 12. Executable vs Process (process.c)

- **Executable** — це файл на диску (наприклад, `program`).
- **Process** — це екземпляр програми, що виконується в пам'яті (має PID, адресний простір, стек, купу тощо).
- Коли ми запускаємо `./program`, операційна система створює новий процес, завантажує в нього код та дані з executable, і починає виконання з точки входу (entry point).

## 13. Memory Map (memory.c)

| Об'єкт                 | Очікувана область | Фактичний результат (приблизно) |
| :--------------------- | :---------------- | :------------------------------ |
| `main`                 | `.text` (code)    | `0x...` (найнижчі адреси)       |
| `global_initialized`   | `.data`           | `0x...` (вище)                  |
| `global_uninitialized` | `.bss`            | `0x...` (поруч з .data)         |
| `static_initialized`   | `.data`           | `0x...` (поруч з global)        |
| `static_uninitialized` | `.bss`            | `0x...` (поруч з global)        |
| `local`                | Stack             | `0x7ffd...` (найвищі адреси)    |
| `dynamic`              | Heap              | `0x55...` (між .bss та stack)   |

**Висновок:** Адреси глобальних та статичних змінних знаходяться близько одна до одної (у секціях `.data` та `.bss`). Локальні змінні — у стеку (найвищі адреси). Динамічна пам'ять — у купі (проміжна область).

## 14. ASLR (Address Space Layout Randomization)

При кожному запуску програми адреси змінюються. Це не помилка, а механізм безпеки ASLR, який рандомізує розташування областей пам'яті, щоб ускладнити експлуатацію вразливостей.

## 15. Stack Experiment (stack.c)

Адреси `&a`, `&b`, `&c` змінюються при вкладених викликах. Зазвичай вони зменшуються (оскільки стек росте вниз на x86-64). Це узгоджується з моделлю стеку.

## 16. Heap Experiment (heap.c)

Адреси `a`, `b`, `c` (отримані через `malloc`) зазвичай послідовні (але не завжди). Головне — вони знаходяться в купі, окремо від стеку.

## 18. Відповіді на контрольні питання

1. **Які основні етапи проходить C-програма до створення executable?** — Preprocessing, Compilation, Assembly, Linking.
2. **Що робить preprocessor?** — Обробляє директиви `#include`, `#define`, макрокоманди тощо.
3. **Що створює compiler?** — Assembly-код з C-коду.
4. **Що робить assembler?** — Перетворює Assembly-код на object file (machine code).
5. **Що містить object file?** — Machine code, таблицю символів, інформацію для лінкера (relocations).
6. **Навіщо потрібен linker?** — Для об'єднання object files та бібліотек в один executable, а також для вирішення undefined symbols.
7. **Що означає `undefined reference`?** — Лінкер не знайшов реалізацію функції або змінної, яка оголошена в коді.
8. **Що таке symbol?** — Ім'я функції або змінної, яке використовується для зв'язування.
9. **Чим header file відрізняється від library?** — Header містить оголошення (інтерфейс), library — реалізацію.
10. **Що таке ELF?** — Executable and Linkable Format, стандартний формат файлів для Linux.
11. **Що зазвичай містить `.text`?** — Машинний код.
12. **Що зазвичай містить `.rodata`?** — Константи (рядки, літерали).
13. **У чому різниця між `.data` та `.bss`?** — `.data` містить ініціалізовані дані, `.bss` — неініціалізовані (заповнюються нулями під час завантаження).
14. **Чому велика `.bss` не обов'язково збільшує розмір executable?** — Тому що `.bss` не зберігається у файлі, лише її розмір у заголовку.
15. **Що показує `ldd`?** — Список динамічних бібліотек, від яких залежить executable.
16. **Чим executable відрізняється від process?** — Executable — це файл на диску, process — це екземпляр програми в пам'яті.
17. **Де концептуально розташовуються local variables?** — У стеку.
18. **Для чого використовується heap?** — Для динамічного виділення пам'яті (`malloc`, `calloc`).
19. **Яка різниця між stack та heap?** — Stack — автоматичне виділення/звільнення, швидкий; heap — ручне, повільніший, але гнучкіший.
20. **Чому адреси можуть змінюватися між запусками?** — Через ASLR (Address Space Layout Randomization).
21. **Що таке temporal locality?** — Властивість програм звертатися до тих самих даних повторно протягом короткого часу.
22. **Що таке spatial locality?** — Властивість програм звертатися до даних, що знаходяться близько в пам'яті.
